## 2. [부하모델.md](부하모델.md)

왜 400 RPS 인가 — DAU 5만에서 목표 부하를 유도한 과정.

- 평시 피크 83 RPS(동접 1,250) / 스파이크 417 RPS 를 어떻게 계산했는가
- closed-loop 와 open-loop 의 차이, 그리고 **이번에 갱신된 실행 현황**
  (spike형 실행됨 / breakpoint형 미실행)

**꼬리질문 대비**: "왜 그 숫자로 시험했나" → 임의로 VU 를 고른 게 아니라
DAU → 피크 집중률 → 세션 길이 → 요청 간격 순으로 유도했다.

## 5. WS 부하시험 — 시험 하네스가 자기 자신을 DDoS 했다

문서가 아니라 커밋으로 남은 건. `loadtest/ws-chat-real.js` 와
[12-메시지처리량](loadtest/results/12-메시지처리량/) 결과.

```
2026-08-31 ws100: 연결 99 성공 / 310,499 실패
초당 837 iteration, 6분간 310,598 세션 시도, ws_delivered 31건
```

**원인이 서버가 아니라 시험 도구였다.** 연결이 거절돼도 VU 가 즉시 다음 iteration 을 돌아
초당 수백 회로 증폭됐고, 그 폭주가 인그레스 rate limit(DDoS 방어)에 스스로 걸려 다시 거절되는
자기강화 루프가 됐다. 처방은 실패 시 `sleep(3)` backoff.

**복습 포인트**: 이 회차 수치는 서버 한계가 아니라 하네스의 재시도 폭주를 잰 것이므로
성능 근거로 인용하면 안 된다. 반증된 회차도 기록으로 남긴다.

**아직 열려 있는 것**: 같은 시간대에 chat 파드가 있던 노드(45-39)가 메모리 고갈로 NotReady 였다.
연결 실패에 그 영향이 섞여 있을 수 있어 재측정 전까지 원인을 하네스 단독으로 확정하지 않는다.

관련 커밋: `e0e8904`

## 6. 배포가 노드를 죽인 사건 (08-30, 08-31 두 번)

상세는 [toy-chat `docs/추후개선점.md`](../../toy-chat/docs/추후개선점.md) 1·2번.
여기서는 인프라 관점 요약만.

```
죽기 직전 ip-172-31-45-39 실측 (t3.small = 2048MB)
  chat-service 798MB + auth-service 558MB + alloy 119MB + node-exporter 9MB = 1483MB
  + OS/kubelet 약 300MB = 약 1800MB
  node available: 131MB → 94 → 65 → 63 → (신호 끊김)
  CPU: 11% → 30% → 78% → 80% 고정   ← 메모리 스래싱
```

- 기본 `maxSurge: 1` 은 새 파드를 먼저 띄운다 → 여유 63MB 노드에 800MB JVM 을 하나 더 → 사망
- 처방은 `maxSurge: 0` (manifest 반영 완료, 클러스터 직접 적용은 대기)
- chat 798MB 중 **231MB 가 off-heap** (heap 322 + nonheap 245 = 567MB 뿐)
- 노드가 죽으면 파드가 갈 곳이 없어 Pending 교착 — 어느 노드에도 800MB 여유가 없다

**복습 포인트**: 이건 [개선점.md](개선/개선점.md) 9번 "배포 = 용량 이벤트"가 실제로 터진 것이다.
문서에 위험으로 적어둔 항목이 그대로 사고가 됐다.

## 이 기간에 배운 것 중 일반화되는 것

1. **측정 도구가 측정 대상을 교란할 수 있다.** 부하 하네스가 rate limit 에 걸려 자기 자신을
   DDoS 하면, 나오는 숫자는 서버 성능이 아니라 하네스의 재시도 특성이다.

2. **"안 했다"고 적힌 것을 주기적으로 검증한다.** 개선점 6번은 이미 한 실험을 미실행으로
   적어두고 있었다. 문서와 실측이 어긋나면 문서가 아니라 실측이 정답이다.

3. **위험으로 적어둔 것이 사고가 된다.** "배포 = 용량 이벤트"는 개선점 9번에 이미 있었는데
   처방(maxSurge + PDB)을 미루는 사이 두 번 터졌다.

4. **원인을 단독으로 확정하지 않는다.** WS 시험 실패에는 하네스 폭주와 노드 사망이 같은
   시간대에 겹쳐 있다. 하나로 단정하지 말고 재측정 조건을 먼저 갖춘다.

5. **실측이 서술보다 강하다.** "메모리가 부족한 것 같다"가 아니라
   "available 131MB → 63MB, CPU 80% 고정, 파드 합계 1483MB / 노드 2048MB".
