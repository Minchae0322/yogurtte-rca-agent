  (+3.9%/+5.0%).** 즉 ② 경로는 어느 한 값을 편들지 않고 **그날 프로브한 값을 매번 지지한다** —
  "회차마다 재라"는 규칙에 대한 독립 검증이다.
- 출력은 `out 13,269`(탐색 3,030 + 분석 10,239). 분석 out이 회차 1(11,070) 대비 **−7.5%**로,
  AU-4에서 25점 차를 만든 **분량 변수가 이 문항 두 회차 사이에서는 통제됐다.**

### ④ 재현 — 정상 피드 생성 트레이스 2건이 있었는데 못 봤다

**채점자 실측** (Tempo `{ name = "http post /feeds" }`, 스윕 창 전체 1시간):

```
00:56:20.576  6a694fb41a63bb565d3423ea61bc21f5   153ms   200   ← baseline
00:56:32.321  6a694fc02926ea82d0bdbb4434237626    74ms   500   ← 주입 (에이전트가 고른 것)
00:57:33.200  6a694ffdda251e01ce9ab659777eb361   138ms   200   ← 복구 확인
```

**앵커가 B(대조군)로 예시한 "정상 피드 생성 대조"가 Tempo에 실재했고, 에이전트는 도달할 수 없었다.**
탐색 스윕이 `{ status = error }`로만 검색하기 때문이다 — AP-2 회차 2가 등재한 결함 ④와 **같은 뿌리**다.
거기서는 traceId를 못 골라 트레이스가 통째로 사라졌고, 여기서는 traceId는 골랐지만
**대조군을 만들 수 없었다.** 증상이 다를 뿐 원인은 하나다.

**그럼에도 B는 충족으로 봤다.** anchors-v2.md 서문이 *"탐색 15의 T·B 기준은 전 문항 공통
([rubric-v3 §3])"* 이라고 위임했고, §3의 B 정의는 **"정상 구간 대조 또는 부재 신호 활용"**
(택일)이다. 에이전트는 둘 다 했다.

- **부재 신호**: chat 로그 0건 · Kafka producer span 부재 · ERROR 버킷 13개 중 12개가 0 · auth/chat 전 구간 0
- **정상 구간 대조(메트릭 대체)**: "content-service 파드에서 유사한 DB 활동 구간이 2회 더
  관측되나 에러 로그가 없어 **성공한 것으로 보이며**, 이는 '특정 입력에서만 터지는 결함'이라는
  해석을 뒷받침한다" — 트레이스가 막히자 `hikaricp_connections_active` 구간으로 대조군을 **스스로 만들었다**

> **채점자 주**: 에이전트가 인용한 두 구간(01:00:15~01:01:00, 01:02:15~01:03:00)은 위 정상
> 피드 생성 2건(00:56:20 · 00:57:33)이 **아니다** — 창 안 다른 트래픽이다. 대조 논증 자체는
> 성립하지만, **앵커가 의도한 대조는 여전히 미수행**이다. 도구를 고치면 이 항목의 근거가
> 메트릭 프록시에서 트레이스 직접 대조로 승격된다.

### ⑤ 신규 — 로그가 컨텍스트에 이중으로 실린다

**채점자 실측** (`reports/raw/`의 원본 응답 2건):

```
loki-error-warn.json   streams=2  lines=4  unique=4   5,709 B
loki-trace-id.json     streams=2  lines=4  unique=4   5,708 B
                                   ↓ 두 채널이 같은 4줄을 각각 반환
리포트 "로그 원문 (8 / 전체 8줄)"  →  4줄 × 2회 중복
```

`errorWarnQuery`(창+서비스 기준)와 traceId 단위 조회가 **같은 줄을 각각 가져오는데 병합 시
중복 제거가 없다.** 이 회차는 115,328자 컨텍스트 중 약 5.7KB(≈5%)가 순수 중복이고,
로그가 많은 문항일수록 커진다.

- **에이전트는 속지 않았다** — *"창 내 ERROR/WARN 조회 결과는 **총 4줄**, 전부 이 traceId뿐(`totalEntriesReturned: 4`)"* 로 고유 줄 수를 정확히 셌다. 채점에 영향 없음.
- **비용 항목이다.** 이 회차가 최고 비용($1.3628)이라 더 눈에 띈다.
- 수정: 어셈블 단계에서 `(timestamp, line)` 기준 dedup. 두 채널을 유지하되 합칠 때만 접는다.
