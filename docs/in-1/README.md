# IN-1 — Redis 다운 × 3개 서비스 동시 이상 (회차별 기록)

toy-content `docs/chaos/` RUNBOOK의 IN-1 문항. **복합 장애 문항** — 하나의 인프라(Redis)가
죽으면 서비스마다 **다른 증상**이 나는데, 그 셋을 한 근원으로 수렴시킬 수 있는지를 잰다.
문항 전체 결과 종합은 toy-content `docs/chaos/RESULTS.md`,
폴더 구성 방식은 [`../ch-1/README.md`](../ch-1/README.md)와 동일.

## 이 문항의 성격 — 질문이 증상을 **따로** 준다

질문 문안이 증상 3건을 나열한다:

```
① 로그인이 느리다   ② 친구가 접속해 있는데 오프라인으로 보인다   ③ 피드에 작성자 이름이 이상하다
```

**셋을 개별 장애로 쪼개면 0점이고, 한 근원으로 묶어야 만점이다.** 그러려면 탐색 단계에서
**여러 서비스를 함께 훑어야** 하므로, 앵커가 *"탐색 실패가 오귀인으로 번지는 유일한 문항"* 이라
못박아 두었다.

**auth 오귀인이 함정이다.** Redis가 죽으면 캐시 미스로 auth 직행이 늘어 **auth가 느려 보인다.**
질문 ①이 그 유인을 준다.

## 회차 인덱스

| 회차 | 일시(UTC) | 입력 | 다운 | 결말 | RCA 조사 | 문서 |
|---|---|---|---|---|---|---|
| 1 | 07-29 07:28:00~07:31:00 (3분) | **자연어** | Redis `docker stop` (172.31.46.124:6379) | 세 서비스 모두 `up=1` 유지 · 피드 **200인데 16~20초** · 캐시 조회/저장 전량 실패 | O | [round-1.md](round-1.md) |

> **회차 1 결과 (2026-07-29): 98 / 100** — anchors-v2 · 루브릭 v3 6항목.
> **채점자 판정 2건**(영향·조치, 범위 93~100).
>
> **세 증상을 Redis 하나로 수렴시켰다** — *"세 증상 모두 07:27:34 UTC경 시작된 Redis 단절
> **하나로 설명 가능**"*. 그리고 **auth 함정을 피했다** — auth를 원인으로도, 무죄로도 확정하지
> 않고 *"'정상 확정'이 아니라 **관측 신호 없음**으로 둔다"* 로 처리했다.
>
> **교차 서비스성을 밀리초로 입증했다** — 같은 Redis 대상 같은 메시지가
> content `qnxk6` 16:27:34.185 / content `scw7k` 16:27:34.234 / chat `w7bf7` 16:27:34.255에
> 거의 동시 시작. *"서로 다른 노드의 pod가 동시에 실패 → **Redis 서버 측 사건**"*.
>
> 감점 2는 6) 조치 — 앵커가 요구한 **캐시 재적재 확인**이 없다. 상세는 [round-1.md](round-1.md).
