# 결함 — 리포트가 사실과 어긋난 것

## ① 실행 1: 반증된 주장 *"토픽 자체가 없음"*

실행 1 후보 1의 근거에 이런 항목이 있다.

> **토픽 자체가 없음**: `Error while fetching metadata with correlation id 480 : {user.notifications=UNKNOWN_TOPIC_OR_PARTITION}` (10:23:39.576), 다른 파드에서는 `… {user.notifications=INVALID_REPLICATION_FACTOR}` (10:23:39.590). `kafka_brokers=1`인데 **요구 replication factor가 그보다 커서 자동 생성이 실패하는 형태**.

**채점자 실측으로 반증된다.**

| 실측 | 값 | 반증하는 것 |
|---|---|---|
| Loki `UNKNOWN_TOPIC_OR_PARTITION\|INVALID_REPLICATION_FACTOR` (01:18~01:40Z) | **총 2줄**, 01:23:39.576 · 01:23:39.590 | `up{job=kafka}` 마지막 0 샘플이 01:23:36Z, 복귀 01:24:06Z — **두 줄 모두 브로커 재기동 순간**이고 그 뒤로 재출현 없음 |
| Tempo `{name="notification-publish"}` 01:20:13Z | **3ms · `STATUS_CODE_OK`**, chat `user-notification-service#process-notification` 778ms 소비 완료 | 주입 **84초 전에 같은 토픽으로 발행·소비가 정상 성립** — 토픽은 실재했다 |
| ⓒ `kafka_consumergroup_lag{topic="user.notifications"}` | 파티션 **0~5 전 구간 시계열 존재** | 토픽이 없으면 파티션 시계열이 나오지 않는다 |

**즉 그 두 줄은 브로커가 살아나는 동안의 과도 상태**이고, 실행 1은 그것을 **정상 상태의
구성 결함**으로 승격시켰다. `INVALID_REPLICATION_FACTOR`에서 *"요구 RF > 브로커 수"* 라는
메커니즘까지 지어냈는데 그 값을 관측한 적은 없다. 대가로 **조치 10건 중 2건이 헛짚었다.**

**복구 신호는 세 채널에 다 있었다** — 신호 부재가 아니다.

| 채널 | 복구 신호 | 실행 1 |
|---|---|---|
| `up{job="kafka"}` | 0 → **1 복귀 01:24:06Z** | 구간의 끝(`~01:23:45Z`)으로 인용 — 사실상 사용 |
| `kafka_brokers` | 결손 01:20:26 → **01:24:11 재개** | 결손 구간(`~01:24:00Z`)으로 인용 — 사실상 사용 |
| 탐색 후보 INC-6 | 신호 목록에 **`up 0 → 1`** 명시 | 후보로 선택됨 |
| Loki 01:23:39 두 줄 | **브로커 기동 직후 메타데이터 재조회** | 🔴 *"토픽 자체가 없음"* 으로 오독 |

**같은 사건을 두 채널에서는 "복구"로 읽고 한 채널에서는 "구성 결함"으로 읽었다.**
기전은 **채널 간 시각 대조 부재**다. **그리고 실행 2가 같은 자리에서 반증을 붙였으므로,
이것은 지시 부재가 아니라 분산일 가능성이 크다**(넘기는 것 ③ 약화 근거).

**회차 1의 재발은 아니다** — 회차 1은 *"토픽 부재"를 **1순위로** 올려 브로커 다운을 놓친 것*이고,
실행 1은 브로커 다운을 1순위로 확정한 **뒤에** 덧붙였다. 1)이 40점인 이유가 그것이다.

## ② 실행 2: 타임아웃 설정 이름을 틀렸다

> 조치 7: … 부수적으로 **`delivery.timeout.ms`(현재 60초)** 만큼 `notification-*` 스레드가
> 점유되는 것도 검토.

60초를 만든 설정은 **`max.block.ms`**(기본 60000ms)다 — 에러 원문
`Topic … not present in metadata after **60000 ms**`가 그 지문이다.
`delivery.timeout.ms`는 기본 120000ms이고 발행 후 전체 배달 기한이라 다른 손잡이다.

**실행 1은 이것을 맞게 썼다**(*"`max.block.ms`를 60초에서 낮춰"*). 2) 근거는 에러 원문
인용으로 대조가 성립하므로 감점하지 않았으나, **조치가 엉뚱한 손잡이를 가리킨다**는 사실은
기록한다. — **실행 1↔2가 서로의 결함을 하나씩 갖고 있다.**

# 실행 1 직후 세웠던 가설이 반증됐다

실행 1만 보고 이렇게 적었다.

> **가설**: *"창이 넓어 무관 신호가 들어오면 조치 절이 잠식돼 6)에서 깎인다."*
> 근거로 조치 10칸 중 5칸이 (a) 반증된 토픽 가설 3칸 (b) IN-1 Redis 잔여 2칸으로 갔고,
> 그 자리가 회차 2에서 미도착분 처리 3칸이 있던 자리라는 것을 들었다.

**실행 2가 반증했다 — 창을 좁히지 않고 그대로 뒀는데 미도착분 항목이 나왔다.**

| | 실행 1 | 실행 2 |
|---|---:|---:|
| 컨텍스트 | 374,186자 | **374,106자** |
| 분석 입력 토큰 | 211,466 | **211,767** |
