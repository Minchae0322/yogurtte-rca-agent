**두 실행의 1순위가 갈렸다**


# 왜 C-6가 1)을 깎았나 — 랭킹의 용도가 바뀌었다

C-6 문언은 *"관측으로 반증된 후보는 랭킹에 올리지 말고 '배제된 후보' 절에 사유와 함께 적는다"* 였다.

```text
회차 3 — 랭킹 = 경쟁 가설 3개
  1. Kafka 브로커 다운        ← 정답
  2. 공통 호스트 단절          ← 스스로 반증
  3. 소비측 문제               ← 스스로 반증

실행 A — 반증된 2·3이 "배제된 후보" 절로 빠짐 → 랭킹 3칸이 빔
  1. 토픽 부재         ┐
  2. 브로커 단절       ├ 빈 칸을 다른 가설이 아니라 한 인과 사슬의 하위 단계로 채웠다
  3. Redis             ┘
```

빈 칸이 **경쟁 가설**이 아니라 **같은 사건의 단계**로 채워졌고, **확신도 순 정렬**이
*로그에 문구가 직접 찍힌 쪽(틀린 쪽)* 을 1위로 올렸다. 브로커 다운은 근거가 메트릭이라 확신도 중간으로 밀렸다.

## 분산이 아니라는 근거

| | 회차2 실1 | 회차2 실2 | 회차3 실1 | 회차3 실2 | **실행 A** | **실행 B** |
|---|---:|---:|---:|---:|---:|---:|
| 1) 원인 | 40 | 40 | 40 | 40 | **30** | **40** |

**1)은 다섯 실행 연속 40이었고, 이 문항에서 흔들린 것은 5)·6)뿐이었다.**
30은 관측된 분산 범위 밖이고, 바뀐 변수는 프롬프트 한 줄뿐이며, 그중 랭킹을 건드린 것은 C-6 하나다.
**실행 B가 그 줄만 되돌려 40을 복원했으므로 귀속이 닫힌다.**

## 가장 얄궂은 부분

이 회차가 고치려던 문제는 **"판단은 맞는데 배치가 틀려서 감점"** 이었다.
실행 A는 **감별을 본문에서 하고 랭킹만 반대로 놓았다** — 정확히 같은 모양이고,
**그것을 고치려는 변경이 원인이었다.**

# 토큰 — 🔴 지표에 결함이 있다

| | 실행 A | 실행 B |
|---|---:|---:|
| `contextChars` | 374,128 | **374,144** (차이 16자) |
| `cacheCreationTokens` | 188,578 | 188,215 |
| **`cacheReadTokens`** | 23,449 | **235,113** |
| 총 `in`(분석) | 212,029 | **423,332** |

**컨텍스트는 사실상 같은데 `in`이 두 배다.** `ClaudeCliLlmClient`가

```java
inputTokens = usage.input_tokens + max(cacheRead,0) + max(cacheCreation,0)
```

로 **세 종류를 합산**하기 때문에, 캐시 히트가 나면 같은 내용이 두 번 계상된다.

**따라서 CLAUDE.md §2의 `컨텍스트 토큰 = in − overhead`는 `cacheRead`가 일정할 때만 성립하고,
이 회차에서 그 전제가 깨졌다.**

**그런데 명백한 설명이 코드와 모순된다.**

```java
String prompt = systemPrompt + "\n\n---\n\n" + context;   // 시스템 프롬프트가 맨 앞
```

C-6 한 줄을 지우면 프롬프트 **맨 앞이 바뀌므로 캐시 접두가 그 지점에서 깨져야 하는데**,
`cacheRead`는 오히려 10배로 뛰었다. **기전 미상이다 — 지어내지 않고 미해결로 남긴다.**

| 후보 설명 | 확인 방법 |
|---|---|
| 직전 실행의 캐시 히트 | 프롬프트 변경 없이 연속 2회 실행해 `cacheRead` 추이 관찰 |
| CLI 2.1.221의 캐시 정책 변경 | 2.1.220으로 내려 같은 조사 재현 |
| CLI 내부 보조 호출 합산 (§2.4) | `modelUsage` 원본 보존 후 모델별 분해 |

**이 회차의 토큰 축은 `in`이 아니라 `contextChars` 또는 `cacheCreationTokens`로 읽어야 하고,
그 두 값 기준으로는 두 실행이 동일하다.**

| ③ | T 재측정 — 창 미지정으로 한 번 | 이 회차는 T 미시험 | **검증** |
| ④ | 토큰 지표 결함 (`in` 합산이 캐시에 따라 2배) | 위 §토큰 | **측정 도구** |
