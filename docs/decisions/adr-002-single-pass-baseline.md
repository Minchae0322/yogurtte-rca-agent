# ADR-002. v0는 도구 없는 단일 패스(single-pass)로 만든다

- 날짜: 2026-07-20
- 상태: 채택
- 관련: [strategy.md](../strategy.md) Phase 1

## 배경

에이전트를 만들 때 유행하는 형태는 tool-calling 루프다: LLM에게 Tempo/Loki/Mimir 조회
도구를 주고 스스로 탐색하게 하는 것. 처음부터 그렇게 만들지 않은 이유를 기록한다.

## 검토한 선택지

1. **에이전틱 루프부터 시작**: 유연하고 강력하지만, 멀티턴 호출로 토큰·지연이 크고
   실행마다 경로가 달라 재현이 어렵다. 무엇보다 — 비교할 기준이 없다.
2. **단일 패스 baseline부터**: 코드가 결정적으로 수집·조립하고 LLM은 1회만 호출.
   수집 범위와 비용이 완전히 통제된다.

## 결정

**v0는 단일 패스로 한다.** collect(Tempo/Loki/Mimir) → assemble → LLM 1회 → notify.
루프도 도구도 없다.

핵심 논거는 **대조군 확보**다. "에이전트 루프가 더 낫다"는 주장은 루프가 없는 기준선이
있어야만 증명 가능하다. 또한 단일 패스는 실패를 세 유형으로 깔끔하게 분류하게 해준다
— (a) 컨텍스트에 신호가 있는데 모델이 놓침, (b) 신호 자체가 수집 안 됨, (c) 신호를
보고도 확정 불가. 이 분류가 이후 어디에 투자할지(프롬프트냐, 수집이냐, 코드 연동이냐)를
결정하는 판단 기준이 된다 (strategy.md Phase 3).

## 실측 결과 (실제 prod 트레이스 1건)

| 항목 | 값 |
|---|---|
| 소요 | 76~84s (3회: 76.2s / 83.6s / 79.7s — 대부분 LLM 75~81s) |
| 수집 소요 | Tempo 0.6~1.1s, Loki 0.2~0.3s, Mimir 0.4~0.8s |
| 토큰 | in 42,651~42,774 / out 4,950~5,056 (재현성: 입력 편차 ±0.3%) |
| 비용 | $0.42~0.43 / 조사 |
| 컨텍스트 | 40,981~41,055 chars |

분석 품질: content 동기 응답(129.8ms)은 정상으로 배제하고, Kafka 뒤 chat의
`push-dispatcher#dispatch` **996ms 중 994ms가 자식 span으로 설명되지 않는 갭**임을
1순위 후보로 특정했다. GC pause·커넥션 pending이 0인 것을 들어 경쟁 가설을 반증했고,
로그 부재를 이유로 확신도를 스스로 낮췄다("데이터 부족" 명시).

**단일 패스의 한계도 그대로 드러났다**: 위치는 특정했지만 원인(무엇이 994ms를
소비하는가)은 확정하지 못했다. 이 실측된 한계가 코드 인지 RCA(Phase 4)의 진입
근거이며, "필요해서 확장한다"를 숫자로 뒷받침한다.
