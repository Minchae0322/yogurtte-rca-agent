## 잘한 것

- **본질 정답**: "안 온 게 아니라 4분 늦게 처리" + "소비자 파드 부재가 원인". 발행→소비 **241.4초 갭**을 ns 타임스탬프로 확정하고 발행측을 무결 판정.
- **메트릭 고고학**: 구 파드의 `jvm_gc_pause` 시계열 소멸과 신 파드의 `hikaricp` 첫 등장을 교차시켜 "소비자 부재 창"을 재구성 — 트레이스 밖 신호(파드 수준 시계열의 출현/소멸)를 능동적으로 증거화한 첫 사례. 부재의 **사유**(스케일다운/OOM/롤링)는 k8s 이벤트가 수집 범위에 없어 미확정으로 남겼는데, 이는 데이터 밖이므로 정당한 유보다.
- **영향 판정 정확 + 정직한 한계 표명**: 늦은 consume이 원 트레이스에 붙어 있어 지연/유실을 바르게 구분했고, "최종 FCM/WS 발송은 계측 공백으로 미확정"이라며 [NF-02](nf-02-fcm-call-no-timeout-no-span.md)(FCM span 부재)를 독립 재발견.

## 4회 조사로 확정된 패턴

1. **영향 판정 정확도 = trace 연속성.** CH-1 r3(DLQ에서 trace 단절 → "유실" 오판) / IN-2(체인이 진짜 끊김 → "유실" 정답) / CH-2(백로그 소비가 같은 trace에 연속 → "지연" 정답). 에이전트는 trace가 이어진 만큼만 결말을 안다 — [NF-08](nf-08-dlq-trace-discontinuity.md)의 수리가 왜 에이전트 성능 문제이기도 한지의 근거.
2. **-120s 시각 밀림은 어셈블러 버그로 확정.** 4회 중 3회 재발인데, 이번 리포트는 **raw ns와 변환 시각을 병기** — ns(=09:49:30)는 정확하고 변환문(09:47:30)만 window padding(120s)만큼 이르다. LLM 앵커링 가설(AE-03)을 폐기하고 어셈블 단계의 시각 포맷 결함으로 좁힘. 수정 위치: 컨텍스트 시각 표기 생성부.
3. **부재 신호 수집 공백 지속**: `kafka_consumer_fetch_manager_records_lag`(앱 메트릭)는 소비자가 죽으면 함께 사라지는 메트릭이라 이 문항에선 구조적으로 무용 — exporter의 `kafka_consumergroup_lag`(계단 상승→수직 낙하가 그대로 남음)로 교체해야 한다. Loki 셀렉터 결함도 4회 연속.
