## 이 문항이 특별한 이유 — 트레이스가 원리적으로 무신호다

조사 전 소급 채록으로 확인한 사실:

| | baseline (01:19:58) | symptom (01:22:12) |
|---|---|---|
| span 수 | 65 | 65 |
| 구성 | `http get /feeds/scroll` → `secured request` → `connection` → `query`×N | 동일 |
| `user-service` client span | **없음** | **없음** |
| duration | 165.75ms | 123.24ms |

user 캐시(TTL 10분) 히트라 **auth가 살아 있을 때도 호출하지 않는다.** 즉 두 트레이스는 구별
불가능하고, 로그인 503은 auth pod이 0이라 트레이스 자체가 생성되지 않는다. **v0의 입력 전제
("traceId 하나로 시작")가 가장 불리하게 걸리는 문항**이다.

## 잘한 것

- **메트릭 시계열 단절만으로 원인 확정.** `hikaricp_connections_active`·
  `hikaricp_connections_pending`·`rate(jvm_gc_pause_seconds_sum[5m])` **3개 계열이 동일
  timestamp(1785115317)에 동시 종료**, 같은 창의 content·chat은 01:24:12까지 연속,
  후속 파드 시계열 미등장 — 이 셋을 엮어 "auth 파드 가용성 상실"에 도달했다.
- **같은 노드 배제.** auth 파드 IP `10.42.3.38`과 같은 `/24` 대역의 `content-service`
  파드(`10.42.3.39`)가 정상 보고함을 근거로 노드 장애 후보를 스스로 기각. CH-1 회차 2의
  "같은 호스트 Redis 0.5ms 정상 → 호스트 장애 배제"와 **같은 추론 패턴이 재현**됐다.
- **증상과 구조의 연결.** 트레이스의 필터체인에 `JwtAuthenticationFilter` 통과 이벤트는
  있는데 auth로 나가는 CLIENT span은 없다는 점에서 "토큰 검증은 content 로컬, auth는 발급에만
  필요" 구조를 추론하고, 그래서 **기존 사용자 피드 조회는 정상인데 신규 로그인만 실패**한다는
  관측과 일치시켰다. 실제 구조(캐시 히트로 decoupling)와 다른 경로지만 결론은 정확하다.
- ~~**자기 결함 진단이 진전했다.**~~ **← 무효 (2026-07-27 정정).** 리포트는 Loki 응답의
  `totalStreams: 0`을 근거로 "라벨 셀렉터가 어떤 스트림도 매치하지 못했다"고 원인을
  특정했으나, **이 회차는 `CLAUDE.md`가 컨텍스트에 로드된 상태였다** — 그 파일에 Loki
  라벨 스키마와 `errorWarnQuery`의 결함이 그대로 적혀 있다. **자력 진단인지 지침 복창인지
  구별할 수 없으므로 성과로 계상하지 않는다.** 경위와 차단책은
  [v0.1 개선 계획 §0](../v0.1-plan.md)。
- **입력 자체를 의심했다.** 리포트 서두에 "제공된 traceId는 로그인 요청이 아니다"라고 먼저
  밝히고, 그 위에서 판단 근거를 메트릭으로 한정했다.

## 못한 것 — 복구 판정 오판 (책임은 설정에 있다)

"그 이후 복구되지 않음", "지속적 부재(CrashLoopBackOff 또는 미복구)"로 판정했으나 실제
원복은 01:22:24다. **에이전트 잘못이 아니다**:

- 수집 창: 01:20:12 ~ **01:24:13**
- 신 파드 첫 스크레이프: **01:25:28** → 창 밖 **1분 15초**

창 안에 복구 증거가 존재하지 않았다. `RCA_WINDOW_PADDING_SECONDS=120`이 이 문항의 복구
관측에 부족하다 — 새 앵커가 "10분 내 미도착" 판정을 요구하는 이상 **창이 복구 시점을
포함하도록 늘리거나 후행 창을 별도 수집해야 한다.**

## 5회 조사로 갱신된 패턴

1. **"부재 신호를 못 쓴다"는 더 이상 관통 패턴이 아니다.** AE-03이 3회 기준으로 세운 명제인데,
   CH-2(메트릭 고고학)에 이어 AU-2에서 **트레이스가 아예 무신호인 상태에서도** 메트릭 부재만으로
   정답에 도달했다. 조건부 능력으로 재분류해야 한다 — 부재가 **대조군과 함께 제시될 때**
   (다른 서비스는 연속인데 이 서비스만 끊김) 쓸 수 있다.
2. **영향/결말 판정 정확도 = 증거가 수집 창 안에 있는가.** AE-04가 "trace 연속성"으로 정식화한
   것의 더 일반적인 형태다. CH-1 회차2는 재처리 로그가 창 **안**에 있었는데 셀렉터 결함으로
   못 봤고, AU-2는 복구 증거가 창 **밖**이라 못 봤다. 원인은 다르지만 결과는 같은 오판이다.
3. **-120s 시각 밀림은 어셈블러 버그가 아니다** — [AE-04](ae-04-rca-v0-ch2-blind-eval.md) 정정 참조.
   `ContextAssembler`에 시각 변환 코드가 없다. 이번 회차는 미재발(5회 중 3회 재발).
4. **Loki 셀렉터 결함 5회 연속.** 이번엔 에이전트가 `totalStreams: 0`으로 원인까지 짚었다.
