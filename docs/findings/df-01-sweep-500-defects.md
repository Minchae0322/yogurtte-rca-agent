# DF-01. 읽기 API 순회에서 발견된 500 고정 결함 3군

- 분류: **결함** (개선점이 아니라 기능 불능) | 상태: 각 2회 재현 (일시 오류 아님)
- 발견 경위: 정상 상황 GET 전용 순회 79회 (`scripts/api-sweep.sh`, 2026-07-24)

## 결함 목록

| # | 엔드포인트 | 증상 | 재현 |
|---|---|---|---|
| 1 | `GET /api/content/categories/popular` | 500 (66B 에러 body) | 2/2 |
| 2 | `GET /api/auth/user/1/following` · `/followers` | 500 (66B) — 팔로우 목록 양방향 모두 | 2/2 |
| 3 | `POST /files/upload` **200** → `GET /files/download/{id}` **500** · `GET /files/{id}/presigned/download` **500** | 업로드는 성공(fileId 2547 발급)하는데 방금 올린 파일을 내려받지 못함 — **왕복 깨짐** | 1/1 (양 경로 모두) |

## 왜 기록하는가

1. **정상 상황 관측의 가치 입증**: 세 결함 모두 장애 알림 없이 조용히 존재하던
   것들이다. 에러율 대시보드는 트래픽이 있어야 울리는데, 이 엔드포인트들은 호출량이
   적어 보이지 않았다. 읽기 순회가 곧 결함 스캐너였다.
2. **RCA 에이전트의 실전 먹잇감**: 각 500은 Tempo에 ERROR 트레이스를 남겼다. 주입이
   아닌 **자연 발생 결함의 트레이스**로 rca 모드를 평가할 수 있는 드문 기회다
   (chaos 시나리오는 정답을 알고 주입하지만, 이건 원인을 모르는 진짜 문제다).
3. **회귀 게이트**: 세 결함 모두 `scripts/api-sweep.sh`에 포함되어 있어(주석으로 표기),
   수정되면 다음 순회에서 200으로 바뀌는 것이 자동 확인된다.

## 특기 사항 — #3 업로드/다운로드 비대칭

업로드가 200으로 성공하고 fileId까지 발급되는데 다운로드가 500인 것은 전형적인
"쓰기 경로와 읽기 경로의 저장소 불일치" 패턴이다 (S3 키 규칙 불일치, 메타데이터만
저장되고 실체 업로드 실패, 또는 다운로드 쪽 presigned 생성 로직 오류). 원인 확정은
해당 ERROR 트레이스로 rca 모드를 돌려 진행한다 — 이 문서는 관측의 기록이고, 원인
분석은 에이전트 평가를 겸한다.

## 후속

- [ ] 각 결함의 ERROR 트레이스 traceId 확보 (Grafana Explore 또는 Tempo search)
- [ ] rca 모드 조사 → 리포트를 이 문서에 링크
- [ ] 수정 후 api-sweep 재실행으로 회귀 확인 (200 전환)
